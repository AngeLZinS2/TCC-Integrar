P0-02 — SUSPENSÃO DE EMPRESA DEVE SER REAL
==================================================

Problema atual:

Company.is_active = false

bloqueia novo login, porém usuários já autenticados continuam utilizando a API.

Isso precisa ser corrigido.

Quando uma empresa estiver suspensa:

- requests autenticados devem ser bloqueados;
- refresh token deve ser bloqueado;
- sessões existentes devem deixar de funcionar;
- usuário deve receber 401;
- frontend deve ser deslogado.

Implementar isso no BACKEND.

Não confie no Flutter para segurança.

Criar uma autenticação personalizada baseada na JWTAuthentication atual que verifique:

user.is_active
E
user.company.is_active

antes de permitir acesso.

IMPORTANTE:

O Platform Owner NÃO possui company_id e deve continuar funcionando normalmente.

Portanto:

if user is Platform Owner:
    permitir

else:
    verificar user.company.is_active

P0-05 — RECUPERAÇÃO DE SENHA
==================================================

Implementar fluxo completo:

POST /auth/password-reset/

usuário informa e-mail.

Sistema responde SEMPRE com mensagem neutra, por exemplo:

"Se existir uma conta associada a este e-mail, enviaremos instruções para recuperação."

Nunca informar:

"Esse usuário não existe."

Criar token temporário e seguro.

Fluxo:

Esqueci minha senha
        ↓
E-mail
        ↓
Token
        ↓
Nova senha
        ↓
Senha alterada
        ↓
Sessões antigas invalidadas

Criar endpoint para redefinição.

Exemplo:

POST /auth/password-reset/confirm/

Receber:

- token
- nova senha

Aplicar todos os validadores de senha já existentes.

O token deve:

- expirar;
- ser de uso único;
- não ser reutilizável;
- não armazenar senha;
- não aparecer em logs.

P0-06 — LOGOUT E REVOGAÇÃO DE SESSÃO
==================================================

O logout atual apenas remove o token do Flutter.

Precisamos melhorar isso.

Avalie o uso do:

rest_framework_simplejwt.token_blacklist

Se for adequado à arquitetura atual, implemente.

Configurar:

- token blacklist
- rotation
- blacklist após rotation

Criar endpoint:

POST /auth/logout/

O cliente envia o refresh token.

O backend invalida o token.

Depois:

refresh antigo → 401

Também avaliar invalidação de sessões quando:

- senha for alterada;
- senha for resetada;
- usuário for desativado;
- empresa for suspensa.
